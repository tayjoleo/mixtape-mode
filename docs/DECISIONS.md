# Decisions

One line each: date, decision, why. Only things the spec does not already settle.

- 2026-11-21: Shell and reel enums stay semantic (`ShellId`, `ReelId`) and the `<Cassette>` component looks up the colour and the `clear` flag internally. Why: the design reference passes raw colours as props, but the tape format in the spec stores ids, and ids are what survive in the URL.
- 2026-11-21: Shell colours are the eight values from `Main.dc.html`'s script, in the spec's enum order (`clear-green`, `clear-cyan`, `crystal`, `clear-smoke`, `hot-pink`, `sunshine`, `lime`, `jet-black`); reels are the four from the same file. Why: the reference wins on looks, and the orders already match.
- 2026-11-21: Doodle paths are `M`/`L` only, per the spec's `^[ML0-9 ,.-]+$` validator. Why: the sample doodles in `Player.dc.html` use `C` and `Q` curves, but the doodle pad only ever emits `M`/`L`, and the spec wins on behaviour.
- 2026-11-21: Header nav is "My tapes" and "Make a tape" only. Why: Templates and Gallery are out of scope for v1 (spec section 9), so linking to them would be a dead end.
- 2026-11-21: J-card ink pair and misregistration live inside the maker rather than on a separate "Design the J-card" page. Why: spec section 6 puts those controls in the maker's Looks part.
- 2026-11-21: "C-60" on the spine and the retail sticker, and "Side A + B" on the riso cover, stay as decorative static text. Why: the tape format has no length field and adding one would cost URL characters for no gain.
- 2026-11-21: The shelf's detail line shows song counts and the seal state instead of the reference's "Sent to 2 people". Why: there is no backend, so send counts are unknowable.
- 2026-11-21: Unavailable tracks are detected with `GET /tracks/{id}?market=from_token` and its `is_playable` field. Why: the spec requires marking them on the J-card but does not say how to find them.
- 2026-11-21: Commit messages carry no tool attribution or co-author lines. Why: spec section 10.
- 2026-11-21: The redirect URI is built as `window.location.origin + import.meta.env.BASE_URL` and checked against a hardcoded registered list, throwing on anything else. Why: the two URIs in the dashboard are exactly the dev origin plus `/` and the Pages origin plus `/mixtape-mode/`, so one rule covers both and a mismatch fails loudly here instead of silently on Spotify's authorize page.
- 2026-11-21: ~~The Premium check moved off `GET /me` and onto the Web Playback SDK's `account_error` event.~~ **Superseded 2026-11-22, see below.** Why: Spotify's February 2026 Dev Mode migration guide lists `product` (along with `country`, `email`, `explicit_content` and `followers`) as removed from the `GET /me` response, so the `product !== 'premium'` test in spec section 4 cannot run. `account_error` is documented as "emitted when the user authenticated does not have a valid Spotify Premium subscription", which is the same signal one step later. The `product` check is still there and still used if the field ever reappears.
- 2026-11-21: The "not on the guest list" screen asks the person for their Spotify email instead of showing it. Why: spec section 4 wanted the email from the error context, but `email` is gone from `GET /me` and a 403 carries no account details.
- 2026-11-21: The `user-read-email` scope stays in the request even though the February 2026 changes make it useless in Development Mode. Why: spec section 4 lists the scopes verbatim, and the spec wins. Worth dropping later so we stop asking for a permission we cannot use.
- 2026-11-21: Milestone 1's hardcoded track is "Hey Ya!" (`2PpruBYCo4H7WOBJ7Q2EwM`), matching the design reference's Side A track 1, verified through Spotify's public oEmbed endpoint. The harness also takes a pasted id, URI or link. Why: a region-locked or wrong id would look exactly like a broken player.
- 2026-11-21: Spotify Web Playback SDK types are hand-written in `src/types/spotify-sdk.d.ts` rather than installed. Why: spec section 10 asks for minimal dependencies, and only a handful of shapes are used.
- 2026-11-21: The J-card tracklist uses Space Grotesk for all Spotify metadata, on phones and on wide screens alike, with handwriting kept for the "Side A" headings. Why: `Player.dc.html`'s bottom sheet already does this, and one tracklist component beats two. Handwriting still carries the cassette label, the spine and the riso cover, so the feel is not lost. `JCard.dc.html`'s Gochi Hand titles remain the look for the unfolded showpiece view if we ever build one.
- 2026-11-21: Each J-card row gets a small bordered "Spotify" pill on the right linking to `external_urls.spotify`. Why: spec section 6 requires a per-track link and neither reference file drew one; a pill is obvious, clears the 44px touch target, and can take the official logo mark once the files land in `public/brand/`.
- 2026-11-21: The song picker expands card 05 of the maker in place (search, "from my playlists", results with add-to-A/B, then the two side lists with up/down/remove) rather than becoming a separate page or a modal. Why: it keeps the single-page maker and the live cassette preview visible while picking, and keyboard reordering is better outside a dialog.
- 2026-11-21: Shelf spines derive entirely from the tape: background from the shell colour, end band from the sticker style, lettering from the tape's font and ink. Why: costs nothing in the URL budget and the spine can never disagree with the cassette it belongs to.
- 2026-11-21: The player and the J-card are laid out horizontally, and a landscape phone is treated as the primary phone orientation for them; the shelf stays vertical. Why: the cassette is a 360x228 landscape object and wants the phone held sideways, the way you would actually hold a tape. A landscape phone and a desktop then share one horizontal layout, and spec section 6's "side panel on wide screens" J-card applies to both. Portrait stays fully usable, falling back to `Player.dc.html`'s layout with a "turn it sideways" hint; nothing is ever blocked behind a rotation.
- 2026-11-21: The OAuth callback handler is wrapped in a module-level `once()` singleton, and StrictMode stays on. Why: StrictMode mounts effects twice in dev, so the first run consumed the state, the verifier and `mm.returnTo`, and the second run failed the state check and restored the URL to the bare base path, losing the tape the listener had opened. `once()` memoises the rejection too, since a consumed authorization code does not become valid on a retry.
- 2026-11-21: `code` and `state` are redacted out of any page URL before it reaches the debug log. Why: the log exists to be copied into a bug report. `state` is only redacted when the URL also carries `code` or `error`, so ordinary API calls like `/me/player/shuffle?state=false` stay readable.
- 2026-11-22: Reversed. `GET /me` on this app **does** return `product`, `email`, `country`, `explicit_content` and `followers`, as the first real login showed. The February 2026 migration guide lists all of them as removed for Development Mode apps, so either this app is not under those restrictions or they were not applied as documented. Spec section 4's `product !== 'premium'` check is therefore restored as the primary Premium gate, which catches a non-Premium account before the SDK starts instead of after. The SDK's `account_error` stays as the backstop, because `product` is still typed optional and because a mobile-only plan may well report `premium` while being unable to stream.
- 2026-11-22: The debug log redacts `email`, `account_id`, `access_token`, `refresh_token` and `code_verifier` from any logged object, centrally in `debug.ts` rather than per call site. Why: the first real `GET /me` wrote the listener's email address and internal account id straight into the log, and the panel exists specifically so that log can be copied and sent to someone else.

- 2026-11-22: Decoding returns a reason (`unreadable`, `version` or `empty`) rather than a bare null. Why: all three show the "chewed up" screen, but keeping them apart means the copy can say something true about which kind of broken it is, and the tests can assert which guard fired.
- 2026-11-22: A tape whose Side A has no valid track ids left after validation is treated as a decode failure, not an empty tape. Why: spec section 5 requires at least one track on Side A, the maker enforces it, and "Side A, Track 1 of 0" is not a thing. Side B surviving as empty is fine and expected.
- 2026-11-22: A repeated track id on the same side is dropped. Why: it is almost certainly a mistake, and the player finds the current track by matching its id against the side's list, so a duplicate would make the position ambiguous.
- 2026-11-22: `clampText` strips control characters, zero-width characters, bidi overrides and the byte order mark, and counts length by code point. Why: React escapes text on render, so this is about the label surviving as a layout, and about an emoji costing one character instead of being sliced in half.
- 2026-11-22: Wire format keys are one character each, `cover` and `sides` are flattened to the top level, booleans are written as 1 and 0, and `to`, `doodles` and Side B are omitted when empty. Measured result: 10 + 10 tracks with three doodles is 1,036 characters of URL, and 10 + 10 with the ink cap fully used is 1,652, against the 2,000 character budget in spec section 5.
- 2026-11-22: `randomString` moved from `pkce.ts` to `lib/random.ts`. Why: tape ids need the same base62 generator, and the PKCE module was the wrong home for it.

- 2026-11-22: The player derives the track index, progress and end-of-side during render from the SDK's reported state, rather than mirroring them into state inside an effect. Why: `react-hooks/set-state-in-effect` flagged the mirroring, and it was right. The only thing still latched in state is "Side A has finished", because lifting the seal has to be remembered rather than recomputed.
- 2026-11-22: Transport controls go through the SDK's own queue (`nextTrack`, `previousTrack`, `seek`) instead of re-issuing `PUT /me/player/play`. Why: playback starts with the whole side as `uris`, so the SDK queue is already exactly the side. No round trip, and it can never wander onto a track that is not on the tape.
- 2026-11-22: `GET /tracks/{id}` calls for the J-card run four at a time and are cached in memory and `sessionStorage`. Why: Development Mode has no batch endpoint, so a full tape is twenty requests; four at a time is quick without inviting a 429.
- 2026-11-22: `SpotifyMark` tries to load the official logo from `public/brand/` and falls back to the labelled placeholder when the file is not there. Why: spec section 2 forbids redrawing the logo, and this way the placeholder disappears by itself the moment the real files are dropped in.
- 2026-11-22: The J-card says "Log in with Spotify to see this one" on each row when logged out, rather than "Loading...". Why: with no login there is nobody to ask, so "Loading" was a lie that never resolved. Found by looking at the screen.
- 2026-11-22: Playback transfers to the deck (`PUT /me/player`) before setting shuffle and repeat, and the settings are retried after playback starts if they are refused. Why: a 404 "Device not found" on `PUT /me/player/shuffle` was traced to the device being `ready` but not the account's _active_ device, which is what happens when arriving at a tape from the shelf replaces one deck with another. Spec section 4 orders this shuffle, repeat, then play; the transfer is an addition, and `PUT /me/player` is already on spec section 2's list of endpoints v1 uses.
- 2026-11-22: Debug log details are truncated at 400 characters. Why: one `GET /tracks/{id}` response is about 1,500 characters and a full tape is twenty of them, which buried the SDK events and errors the log exists to show. Errors and event payloads are far shorter, so nothing useful is cut.
- 2026-11-22: `getPlaylistTracks` tries `/playlists/{id}/items` and falls back to `/playlists/{id}/tracks`, and the reader accepts both the `item` and `track` row shapes. Why: February 2026 renamed the endpoint and its fields for Development Mode apps only, the API will not say which quota mode an app is in, and the dashboard no longer appears to say Development Mode. Trying both costs one extra request in the rare case and removes the guess.
- 2026-11-22: Search always asks for `limit=10`. Why: that is inside Development Mode's cap and inside the ordinary maximum, so it needs no knowledge of the quota mode. "More results" pages with `offset`.
- 2026-11-22: The go / no-go screen has a read-only "Check the API" probe that reports whether batch `GET /tracks` works, whether search honours `limit=50`, and which fields `/me` returns. Why: it settles which quota mode the app is in from the API itself rather than from memory of the dashboard. It goes when the harness does.
- 2026-11-22: The maker is reachable logged out. Why: all the decoration works without Spotify, so only the song picker needs an account, and being asked to log in before you can even look is a worse first impression.
- 2026-11-22: The doodle pad draws the in-progress stroke unsimplified and only runs Ramer-Douglas-Peucker on release. Why: simplifying mid-stroke makes the line visibly crawl behind the pointer.
- 2026-11-22: Spine lettering keeps the tape's own ink only when it clears 4.5:1 against the spine background, and otherwise falls back to whichever of near black or paper white reads better. Why: shell and ink are chosen independently in the maker, so black ink on a jet black shell is something someone can make, and the shelf shipped two unreadable spines until this was added. The fallback has to pick between two colours rather than always going light: pink ink on the hot pink shell fails against white but passes against black.
- 2026-11-22: Shelf spine tilts are seeded from the tape id through a hash with a MurmurHash3 avalanche step. Why: plain FNV-1a left a trailing character's influence in the low bits, so a run of similar ids produced near-identical tilts and every spine leaned the same way. Caught by a test asserting the spread.
- 2026-11-22: The Milestone 1 harness moved from `#/` to `#/check`, reachable from the debug panel. Why: the shelf is the home screen now, but the SDK and API diagnostics are still the quickest way to see what Spotify is doing.
- 2026-11-22: The skip link is a button that focuses `<main>`, not an anchor. Why: routing lives in the hash, so `href="#mm-main"` would navigate to a route that does not exist instead of jumping down the page.
- 2026-11-22: Editing a tape keeps its id and `createdAt`. Why: the shelf is keyed by payload, so a re-made tape is a new entry either way, but keeping the id means the spine does not change its lean when the tape is edited.
